# Signaling Protocol

> **Current state.** Behaviour marked ✅ was verified on 2026-11-17 by
> running `server/server.js` locally (Node v22.17.0) with a black-box
> WebSocket test client. Client-side behaviour (desktop `renderer.js`, phone
> `m.html`) is *code-traced* only.

## Transport

- WebSocket on the same host and port as the HTTP server
  (`wss://<PUBLIC_ORIGIN host>` in production).
- Messages are JSON text frames. The type field is `t`.
- Max payload: 64 KB (`ws` `maxPayload`).
- Server pings every 30 s; a client that has not answered the previous ping
  is terminated.

## Connection admission (HTTP upgrade)

| Condition | Result |
|---|---|
| `Origin` header missing or not in the allow-list | ✅ HTTP 403 "Origin not allowed" |
| Open connections ≥ `MAX_CONNECTIONS` | HTTP 503 "Connection limit reached" *(code-traced)* |

Default allow-list: `PUBLIC_ORIGIN` and `file://`. ✅ A client sending
`Origin: file://` is accepted. That the packaged Electron app really sends
`Origin: file://` is inferred from it working in deployment and has **not**
been captured in this pass.

## Client → server

### `join`
```json
{ "t": "join", "room": "<32 lowercase hex>", "role": "desktop" | "phone" }
```
- Allowed once per socket. A second `join` on the same socket closes it with
  `1008`.
- ✅ Invalid room or role → close `1008` "Invalid room, role, or join rate".
- ✅ Rate limit: **10 join attempts per IP per 60 s window**. Attempts are
  counted *before* room/role validation, so invalid joins also use up the
  quota. Exceeding the limit → close `1008`. The IP is
  `X-Forwarded-For[0]` when `TRUST_PROXY=1`, otherwise the socket address.
- Creating a *new* room when `MAX_ROOMS` rooms already exist → close `1013`
  "Room limit reached" *(code-traced)*.
- ✅ If the room already has a member with the same role, that member gets a
  `peer down` sent to the others and is closed with **`4001` "Replaced by
  reconnect"**, and the new socket takes its place.

On a successful join the server sends `config` to the joiner, then exchanges
`peer up` notifications with the other member (if any).

### `sig`
```json
{ "t": "sig", "data": { ... } }
```
- ✅ Relayed unchanged as `{t:"sig", data}` to the **other** members of the
  room (never echoed back to the sender).
- ✅ Ignored silently if the socket has not joined, or if `data` is not a
  plain object.

`data` shapes used by the clients:

| Shape | Sender | Meaning |
|---|---|---|
| `{ negotiationId, sdp }` | phone | SDP offer |
| `{ negotiationId, sdp }` | desktop | SDP answer |
| `{ negotiationId, ice }` | both | ICE candidate |

`negotiationId` is `"<Date.now()>-<sequence>"`, generated by the phone per
offer. Both clients ignore answers and candidates whose `negotiationId` does
not match the current negotiation. The desktop tears down any existing
`RTCPeerConnection` when a new offer arrives.

### Anything else
- ✅ Non-JSON, or JSON that is not a plain object → close `1008`
  "Invalid message".
- Unknown `t` values on a valid object are ignored *(code-traced)*.

## Server → client

| Message | When |
|---|---|
| `{ "t": "config", "iceServers": [...] }` | ✅ Immediately after a successful join. Defaults to three Google STUN servers. With `TURN_SECRET` set, every entry with a `turn:`/`turns:` URL gets a fresh `username`/`credential` (✅ verified; see [CONFIGURATION.md](CONFIGURATION.md)). |
| `{ "t": "peer", "up": true, "role": "<role>" }` | ✅ Sent to both sides when a second member joins. |
| `{ "t": "peer", "up": false, "role": "<role>" }` | ✅ Sent to the remaining member when a member disconnects or is replaced. |
| `{ "t": "sig", "data": {...} }` | ✅ Relay of the other member's `sig`. |

## Close codes

| Code | Reason text | Client reaction |
|---|---|---|
| `1008` | `Invalid message` / `Invalid room, role, or join rate` | Desktop and phone both auto-retry with backoff |
| `1013` | `Room limit reached` | Auto-retry |
| `4001` | `Replaced by reconnect` | **No retry.** Desktop shows "Another CamShare window took over this session"; phone shows "Another device took over this camera session." |

Note: because clients auto-retry on `1008`, a client that hits the rate
limit will keep retrying (desktop backoff caps at 10 s, phone at 30 s). Each
retry is itself a join attempt.

## Typical sequence

```
Desktop                      Server                        Phone
  │── join(room, desktop) ──▶│                               │
  │◀───────── config ────────│                               │
  │                          │◀──── join(room, phone) ───────│
  │                          │───────── config ─────────────▶│
  │◀──── peer up (phone) ────│──── peer up (desktop) ───────▶│
  │                          │   (user taps Connect Camera)  │
  │◀──── sig {sdp offer} ────│◀──── sig {sdp offer} ─────────│
  │──── sig {sdp answer} ───▶│──── sig {sdp answer} ────────▶│
  │◀═══════ sig {ice} ══════▶│◀═══════ sig {ice} ═══════════▶│
  │◀════════════ WebRTC media (phone → desktop) ═════════════│
```
